# Create Plan

创建简洁、可执行的计划。当用户明确要求与编码任务相关的计划时使用此技能。

## 功能描述

Create Plan Skill 将用户需求转化为单一、可执行的计划，以结构化的方式呈现，包含范围界定、行动项清单和待解决问题。

## 使用方法

### 工作流程

1. **快速扫描上下文**
   - 阅读 `README.md` 和相关文档
   - 浏览相关文件
   - 识别约束条件（语言、框架、CI/测试命令等）

2. **仅在必要时提问**
   - 最多询问 1-2 个问题
   - 仅在无法合理规划时才提问
   - 优先做出合理假设

3. **使用模板创建计划**
   - 简短描述意图和方法
   - 明确界定范围（In/Out）
   - 提供 6-10 个行动项清单
   - 包含测试/验证项
   - 包含边界情况/风险项

### 计划模板

```markdown
# Plan

<1-3句话：我们在做什么，为什么，以及高层方法>

## Scope
- In:
- Out:

## Action items
[ ] <步骤1>
[ ] <步骤2>
[ ] <步骤3>
[ ] <步骤4>
[ ] <步骤5>
[ ] <步骤6>

## Open questions
- <问题1>
- <问题2>
- <问题3>
```

## 使用示例

**用户请求：** "帮我制定一个添加用户认证功能的计划"

**输出示例：**
```markdown
# Plan

为应用添加基于 JWT 的用户认证系统，包括登录、注册和权限验证功能。

## Scope
- In: 用户注册、登录、JWT token 生成、受保护路由
- Out: 第三方登录、密码找回、多因素认证

## Action items
[ ] 设计用户数据模型（用户名、密码哈希、角色）
[ ] 实现用户注册 API 端点
[ ] 实现用户登录和 JWT 生成
[ ] 创建认证中间件保护路由
[ ] 添加密码加密（bcrypt）
[ ] 编写单元测试验证认证流程
[ ] 更新 API 文档

## Open questions
- 密码复杂度要求是什么？
- Token 过期时间设置为多久？
```

## 清单项指导

**好的清单项：**
- 指向可能的文件/模块
- 命名具体的验证方式
- 包含安全发布说明

**避免的清单项：**
- 模糊的步骤（"处理后端"、"做认证"）
- 过多的微步骤
- 代码片段（保持计划与实现无关）

## 注意事项

- 整个工作流程以只读模式运行
- 不要写入或更新文件
- 计划应简洁明了
- 不要在计划前添加元解释
